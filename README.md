# منصة إدارة التدريب الميداني — جامعة القصيم

**كلية اللغات والعلوم الإنسانية · قسم الاجتماع والخدمة الاجتماعية**
رئيس القسم: د. عمر محمد النملة · رئيسة وحدة التدريب الميداني: د. بشرى محمد الدبيخي
مؤسس المنصة ومطورها: **عبدالملك عواض العتيبي** (Founder & Lead Developer) — © 2026، انظر [حقوق الملكية الفكرية](#صفحة-عن-المنصة-والمطور-وحقوق-الملكية-الفكرية)

تطبيق ويب وجوال (PWA) لإدارة التدريب الميداني بالكامل. يشمل التوزيع على الجهات والخطابات الرسمية، والتحضير بالتحديد الجغرافي مع كشف التحضير الوهمي، والسجلات الميدانية بالتوقيع الإلكتروني، والتقييم ورصد الدرجات، ولوحات قيادية لحظية واستراتيجية.

| الطبقة | التقنية |
|---|---|
| الواجهة | Next.js 15 (App Router) + React 19 + Tailwind CSS + مكونات بنمط shadcn/ui، واجهة عربية RTL كاملة |
| الخادم | Next.js Route Handlers (Node.js) |
| قاعدة البيانات | PostgreSQL (محلي أو Supabase) عبر Prisma ORM |
| المصادقة | NextAuth (JWT) + تشفير bcrypt + صلاحيات حسب الدور (RBAC) |
| الخرائط | Leaflet / OpenStreetMap |
| الخطابات والمستندات | PDF رسمي بمقاس A4 عبر Chromium بخطوط مضمّنة، وبصمة SHA-256 ورمز تحقق QR |

## ⚡ تشغيل العرض التوضيحي بأمر واحد

المتطلبات:
- **Node.js 20.6 أو أحدث.**
- **PostgreSQL:** مثبّت محلياً، أو عبر Docker بالأمر `docker compose up -d`.
- **Chrome أو Edge** لتوليد PDF على الخادم. يُكتشف تلقائياً.

   - دراسة حالة معتمدة ومقابلة مرتبطة بها.
   - برنامج جماعي، وقراءة موثقة وفق APA.

## 1) التشغيل السريع (محلياً)

المتطلبات: Node.js 20 أو أحدث، وPostgreSQL 14 أو أحدث (أو مشروع Supabase).

```bash
# 1. تثبيت الحزم
npm install

# 2. إعداد المتغيرات
cp .env.example .env
#   عدّل DATABASE_URL و DIRECT_URL و NEXTAUTH_SECRET (openssl rand -base64 32)

# 3. إنشاء الجداول (ترحيلات SQL في prisma/migrations)
npm run db:deploy                       # = prisma migrate deploy

# 4. بيانات تجريبية (اختياري)
npm run db:seed

# 5. التشغيل
npm run dev        # http://localhost:3000
```

> **قاعدة أُنشئت سابقاً بـ `db push`:** اعتمدها كخط أساس مرة واحدة ثم طبّق الترحيلات الجديدة:
> ```bash
> npx prisma migrate resolve --applied 0001_init
> npm run db:deploy
> ```
> الترحيل `0002_official_forms` **إضافي فقط** (لا حذف لأي جدول أو عمود) ومُختبَر على قاعدة فارغة وعلى قاعدة فيها بيانات.

### الربط مع Supabase

1. أنشئ مشروعاً في Supabase، ثم انسخ رابطي الاتصال من *Project Settings → Database*.
2. ضع رابط الـ **Pooler** (المنفذ 6543، مع `?pgbouncer=true`) في `DATABASE_URL`، والرابط **المباشر** (المنفذ 5432) في `DIRECT_URL`.
3. نفّذ `npx prisma migrate deploy` ثم `npm run db:seed`.

تستخدم المنصة Supabase كقاعدة PostgreSQL فقط، والمصادقة تتم عبر NextAuth. للانتقال إلى Supabase Auth يكفي استبدال `src/lib/auth/*` لأن بقية الطبقات تعتمد على `requireRole()` فقط.

### النشر (Vercel أو خادم خاص)

```bash
npm run build && npm start
```

- **PDF على الخادم:** يتطلب متصفح Chromium. على خادم خاص ثبّت `chromium` واضبط `CHROME_EXECUTABLE_PATH`. على Vercel استخدم `@sparticuz/chromium`. إذا لم يُضبط المتغير يُحوَّل رابط PDF تلقائياً إلى نسخة الطباعة، ويستطيع المستخدم الحفظ بصيغة PDF من المتصفح.
- **المهمة اليومية:** تسجل الغياب آلياً وترفع التنبيهات الحرجة. جدولها بعد نهاية الدوام (مثلاً 15:00 بتوقيت الرياض = 12:00 UTC):
  ```bash
  curl -X POST https://your-domain/api/cron/daily -H "Authorization: Bearer $CRON_SECRET"
  ```
  على Vercel أضف في `vercel.json`: `{"crons":[{"path":"/api/cron/daily","schedule":"0 12 * * 0-4"}]}`. لاحظ أن Vercel Cron يرسل طلب GET، فأضف GET للمسار أو استخدم مجدولاً خارجياً.
- **HTTPS إلزامي:** المتصفحات لا تسمح بتحديد الموقع إلا على HTTPS أو localhost.
- **الهوية الرسمية:** الشعار الرسمي في `public/brand/qu-logo.png` (مستخرج من ملف النماذج الرسمية)، وأيقونات التطبيق مستخرجة من رمزه. كل الألوان من مصدر واحد: `src/lib/brand.ts`.
- **المرفقات:** `STORAGE_DRIVER=local` (قرص الخادم) أو `supabase` (حاوية خاصة، والمفتاح يبقى على الخادم فقط). انظر `.env.example`.
  - يُختار Supabase تلقائياً متى ضُبط `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY`.
  - على Vercel قرص الخادم مؤقت: بلا إعداد Supabase تُرفض المرفقات برسالة واضحة (503) بدل فقدانها لاحقاً.
- **الخطابات وملفات PDF على Vercel:** الشعار والخطوط المضمّنة تُضاف لحزمة الخادم عبر `outputFileTracingIncludes` في `next.config.ts`.
  - إن تعذّرت قراءتها لا تتعطل الصفحة: يُستخدم رابط الشعار العام وخط النظام.
  - لا يوجد Chromium على Vercel، فرابط تنزيل PDF يفتح نسخة الطباعة، ومنها «حفظ كـ PDF» من المتصفح.
- **منطقة التشغيل:** `vercel.json` يثبّت دوال الخادم في `iad1` (شرق أمريكا)، بجوار قاعدة بيانات Supabase في `us-east-1`، فتقل زمن الاستعلامات.

## 3) مرجع الـ API

كل المسارات تتحقق من الدور في الخادم (`requireRole`) وتحصر البيانات بالطلاب المرتبطين بالمستخدم (`placementScope`). الأخطاء تعود بصيغة `{ error, details? }` وبرسائل عربية.

### الحضور والتحضير
| المسار | الدور | الوصف |
|---|---|---|
| `GET /api/attendance/today` | طالب | جهة اليوم ونطاقها وسجل اليوم |
| `POST /api/attendance/check-in` | طالب | تسجيل الحضور: `{ samples[], deviceId }` |
| `POST /api/attendance/check-out` | طالب | تسجيل الانصراف (يحسب الدقائق) |
| `GET /api/attendance?placementId&from&to&approval&suspicious=1` | الجميع (حسب النطاق) | سجل الحضور |
| `POST /api/attendance/approve` | مشرف مؤسسي / رئيس التدريب | اعتماد أو رفض فردي أو جماعي، ويعيد احتساب الساعات |
| `POST /api/attendance/manual` | مشرف مؤسسي | تسجيل غياب أو عذر أو إجازة |
| `POST /api/cron/daily` | Cron (Bearer) | تعليم الغياب والتنبيهات الحرجة |

### التقييم والدرجات
| المسار | الدور | الوصف |
|---|---|---|
| `GET /api/evaluations?placementId` | المشرفان | بنود الاستمارة (حسب الفصل والتخصص) والمسودة المحفوظة |
| `POST /api/evaluations` | المشرفان | حفظ مسودة أو اعتماد مع توقيع (يحدّث الدرجة آلياً) |
| `POST /api/grades/calculate` | رئيس التدريب | احتساب الدرجات النهائية |
| `POST /api/grades/approve` | رئيس التدريب | اعتماد النتائج وقفل التقييمات |
| `GET /api/grades/export?termId` | رئيس التدريب / رئيس القسم | كشف الدرجات CSV (يفتح في Excel بالعربية) |

### جهات التدريب والإعدادات
| المسار | الدور | الوصف |
|---|---|---|
| `GET/POST /api/organizations` | رئيس التدريب | دليل الجهات / إضافة جهة |
| `PATCH/DELETE /api/organizations/:id` | رئيس التدريب | تعديل (يُوثَّق نقل الموقع) / حذف جهة بلا إسنادات |
| `POST /api/organizations/:id/supervisors` | رئيس التدريب | إنشاء حساب مشرف مؤسسي بكلمة مرور مؤقتة |
| `GET /api/geo/resolve?url=` | رئيس التدريب | فك روابط خرائط Google المختصرة (قائمة سماح) |
| `GET/PUT /api/terms/:id/criteria?type=` | رئيس التدريب | بنود استمارة التقييم (تُقفل بعد رصد تقييمات نهائية) |
| `PATCH /api/terms/:id` | رئيس التدريب | الأوزان (تُقفل بعد اعتماد نتائج) والساعات وقواعد الحضور |

### التقارير والسجلات القديمة (أرشيف للقراءة فقط)
بعد التحول إلى النماذج الرسمية، رُحّلت التقارير والسجلات إلى `FieldForm` (انظر [القسم 10](docs/official-forms-architecture.md#10-واجهات-المرحلة-3-والتحول)).

| المسار | الوصف |
|---|---|
| `GET /api/reports`، `GET /api/reports/:id`، `GET /api/logbooks` | قراءة الأرشيف ضمن نطاق المستخدم |
| `POST/PATCH/DELETE` على `/api/reports*` و`/api/logbooks*` | **410**: استخدم `/api/forms` |

### النماذج الرسمية
المرجع الكامل وسير العمل في [`docs/official-forms-architecture.md`](docs/official-forms-architecture.md#9-مرجع-واجهة-النماذج-المرحلة-2).

| المسار | الوصف |
|---|---|
| `GET/POST /api/forms` | قائمة النماذج / إنشاء نموذج بتعبئة مسبقة |
| `GET/PATCH/DELETE /api/forms/:id` | عرض (مع `allowedActions`) / حفظ مسودة / حذف مسودة |
| `POST /api/forms/:id/transition` | رفع، توقيع مؤسسي، اعتماد أكاديمي، إعادة |
| `POST /api/forms/:id/attachments` · `GET /api/attachments/:id` | الشواهد (مع إزالة بيانات الموقع) |

### مخرجات PDF الرسمية (المرحلة 5)
أضف `?format=html` إلى أي مسار للحصول على نسخة للطباعة من المتصفح.

| المسار | الوصف |
|---|---|

## 4) قرارات التصميم المهمة

### التحضير الجغرافي وكشف التزييف
- يجمع العميل **4 قراءات GPS متتالية** خلال 15 ثانية بأعلى دقة، ثم يعيد **الخادم** التحقق من كل شيء. لا يُعتمد على أي حساب يجري في المتصفح.
- **النطاق:** 100 م افتراضياً لكل جهة (قابل للتعديل)، مع هامش لا يتجاوز 25 م لتعويض ضعف الإشارة.
- **تقييم المخاطر** (`src/lib/geo/anti-spoof.ts`): أعلام حاسمة تؤدي إلى **الرفض** (موقع وهمي من النظام، دقة ضعيفة، قراءة قديمة، إحداثيات صفرية)، وأعلام مشبوهة تؤدي إلى **القبول مع الإحالة للمراجعة** (دقة غير واقعية، ثبات تام بين القراءات، سفر مستحيل، إحداثيات منخفضة الدقة، جهاز غير الجهاز المسجل). اجتماع مؤشرين قويين يؤدي إلى الرفض.
- كل محاولة، سواء قُبلت أو رُفضت، تُحفظ في `AttendanceAttempt` للتدقيق.
- **الساعات لا تُحتسب إلا بعد اعتماد المشرف المؤسسي**، وهو خط الدفاع الأخير.
- **حدود معروفة:** لا يمكن لتطبيق ويب كشف تزييف الموقع بنسبة 100%. أقوى إضافة مستقبلية هي تغليف التطبيق بـ Capacitor لقراءة علم `isMock` من نظام أندرويد، والمسار مهيأ لاستقباله (`isMocked`).

### الدرجة النهائية
`40% المشرف المؤسسي + 40% المشرف الأكاديمي + 20% التحضير والسجلات`. الأوزان مخزنة في `AcademicTerm` وقابلة للتعديل لكل فصل، ويُرفض أي مجموع لا يساوي 100. مكوّن التحضير يُحسب هكذا: نصفه لنسبة إنجاز الساعات، ونصفه لنسبة السجلات الأسبوعية المرفوعة، ويُخصم منه درجة عن كل غياب بلا عذر (بحد أقصى نصف المكوّن). سلم التقديرات: A+ من 95، وA من 90 … وF أقل من 60. لا يمكن الاعتماد إذا كان أحد التقييمين ناقصاً.

### إدارة الجهات والإحداثيات
- **منتقي الموقع**: انقر على الخريطة أو اسحب الدبوس، مع طبقة «قمر صناعي» لتحديد المدخل بدقة. يمكن أيضاً لصق رابط خرائط Google (بما فيها الروابط المختصرة `maps.app.goo.gl`) أو استخدام «موقعي الحالي» عند زيارة الجهة.
- في روابط Google من نوع place يُعتمد **دبوس المكان** (`!3d…!4d…`) لا مركز الكاميرا (`@…`)، لأن الأخير قد يبعد عن الموقع الفعلي مئات الأمتار.
- الإحداثيات مقيدة بنطاق المملكة لاكتشاف الأخطاء الشائعة مثل تبديل خط الطول بخط العرض.
- كل تغيير في موقع جهة أو في نطاقها يُسجَّل في سجل التدقيق بالقيم السابقة والجديدة ومسافة النقل، ويظهر تحذير إذا كان للجهة متدربون حاليون.
- **لا تُحذف** جهة لها إسنادات، بل **تُوقَف**، حفاظاً على السجلات التاريخية.

### بنود التقييم
- تُحسب نسبة الطالب من مجموع البنود المنطبقة على **تخصصه**، ويعرض المحرر مجموع كل تخصص لحظياً ويُنصح بأن يكون 100.
- **القفل التلقائي**: بمجرد رصد أول تقييم نهائي باستمارة ما في الفصل تُقفل بنودها، حتى يُقيَّم جميع الطلاب بالمقياس نفسه. كذلك تُقفل الأوزان بعد اعتماد أول نتيجة.

### التقارير الميدانية (نماذج إضافية)
- بعد اعتماد الدليل الرسمي أصبحت قوالب **البحث الميداني، والمسح الاجتماعي، والتقرير الختامي** «نماذج إضافية» (`FieldForm` من نوع `CUSTOM`) تُنشأ من السجل المهني وتمرّ بسير العمل نفسه. أما دراسة الحالة وخطة التدخل وخدمة الجماعة، فحلّت محلها النماذج الرسمية، وسجلاتها السابقة في الأرشيف.
- القوالب الست الأصلية: **دراسة حالة، خطة تدخل اجتماعي، خدمة الجماعة** (للخدمة الاجتماعية)، و**بحث ميداني، مسح اجتماعي** (لعلم الاجتماع)، و**التقرير الختامي** (للتخصصين).
- كل قالب **تعريف تصريحي** في `src/lib/report-templates.ts`، ومنه تُولَّد الواجهة والعرض والطباعة والتحقق في الخادم. لتعديل نموذج أو إضافة حقل يكفي تعديل هذا الملف. التحقق صارم: يرفض الخادم أي حقل غير معرّف أو نوع خاطئ.
- **مسار العمل**: مسودة (مع حفظ تلقائي) ← رفع ← توقيع المشرف المؤسسي أو إعادته ← اعتماد المشرف الأكاديمي بدرجة استرشادية أو إعادته. إعادة تقرير موقَّع تُسقط توقيعه لأن المحتوى سيتغير.
- **السرية**: دراسة الحالة وخدمة الجماعة تفرضان اسماً رمزياً وإقراراً بموافقة العميل.
- الطباعة وحفظ PDF متاحان من المتصفح بصيغة A4 مع الترويسة والتوقيع.

### الجلسات وتسجيل الدخول والخروج
الإعدادات في `src/lib/auth/config.ts` و`src/lib/auth/options.ts`، ويستخدمها الـ middleware نفسها.

- **الجلسة:**
  - 30 يوماً (`session.maxAge` و`jwt.maxAge`)، وهي **منزلقة**: كل طلب لـ `/api/auth/session` يمدّها 30 يوماً جديدة.
  - المتصفح يرسل هذا الطلب كل 5 دقائق والصفحة مفتوحة، وعند العودة إلى التبويب، فلا يخرج المستخدم عند الخمول.
- **الكوكيز:** `HttpOnly` و`SameSite=Lax` صراحةً، و`Secure` مع بادئة `__Secure-` حين يكون `NEXTAUTH_URL` بـ https.
- **حماية الجلسة الطويلة:** يُعاد التحقق من الحساب في القاعدة كل 5 دقائق. الحساب الموقوف تُلغى جلسته، وتغيير الدور يسري دون انتظار انتهاء الجلسة.
- **إعادة التوجيه:**
  - دالة `callbacks.redirect` تعيد **مساراً نسبياً** دائماً، مثل `/login`، فيبقى المستخدم على نطاق الطلب الحالي بدل `NEXTAUTH_URL` الثابت أو `localhost`.
  - تمنع كذلك إعادة التوجيه إلى مواقع خارجية، ومثلها `callbackUrl` في صفحة الدخول.
- **الخروج:** `signOut({ callbackUrl: "/login" })`.
- **الدخول:** بطلب نسبي إلى `/api/auth/callback/credentials`، والنتيجة من رمز الحالة HTTP. لا يُستخدم `signIn()` لأنها لا تقبل روابط الرد النسبية في NextAuth v4.

### رسالة وصول المتدرب للمشرف المؤسسي (اختيارية)
- **التفعيل:** من صفحة المشرف المؤسسي، بطاقة «الإشعارات»: مفتاح تشغيل/إيقاف ورقم الجوال (05XXXXXXXX). معطّلة افتراضياً.
- **متى تُرسل:** مرة واحدة عند أول تحضير ناجح للمتدرب من داخل نطاق المؤسسة في يوم تدريبه. التحضير المرفوض لا يرسل شيئاً.
- **دون إبطاء:** تُرسل بعد الرد على الطالب (`after()` في Next.js)، وفشل الإرسال لا يؤثر على التحضير.
- **المزوّد:** `SMS_PROVIDER` = `taqnyat` أو `unifonic` أو `msegat`، مع `SMS_API_KEY` و`SMS_SENDER` (انظر `.env.example`). بلا مزوّد تُسجَّل المحاولة فقط.
- **السجل:** كل محاولة في `AuditLog` (`sms.arrival`) بنتيجتها، والرقم مخفي (آخر 3 أرقام).
- **قاعدة البيانات:** الترحيل `0004_sms_arrival`. على Vercel يُطبَّق تلقائياً عند كل نشر (`vercel-build` = `prisma migrate deploy` قبل البناء).

### صفحة «عن المنصة والمطور» وحقوق الملكية الفكرية
- **الصفحة `/developer`:** بطاقة المطور، ورؤية المنصة، وصندوق حقوق الملكية الفكرية، وزرا التواصل (البريد وLinkedIn).
- **الوصول:** رابط «عن المنصة والمطور» أسفل القائمة الجانبية لجميع الأدوار، وفي قائمة الجوال. الشريط السفلي للجوال لا يتغير.
- **التذييل:** «تم التطوير بواسطة عبدالملك العتيبي © 2026» أسفل صفحات المنصة وصفحة الدخول وصفحة التحقق. لا يظهر في المستندات الرسمية المطبوعة (PDF).
- **البيانات الوصفية:** `authors` و`creator` و`publisher` في `src/app/layout.tsx`.
- **مصدر واحد للبيانات والنصوص:** `src/lib/developer.ts`.
- **قنوات التواصل:** تُضبط بمتغيرَي البيئة `DEVELOPER_EMAIL` و`DEVELOPER_LINKEDIN_URL`. غير المضبوط منها يظهر زراً معطلاً «يُضاف قريباً».

### التوقيع الإلكتروني
صورة التوقيع (PNG) ومعها **بصمة SHA-256 لمحتوى المستند وقت التوقيع**، إضافة إلى عنوان IP والوقت. أي تعديل لاحق يمكن كشفه بمقارنة البصمة. هذا مُختبَر: أي تعديل مباشر على محتوى تقرير موقَّع في قاعدة البيانات يغيّر البصمة فيُكتشف.
