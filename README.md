# منصة إدارة التدريب الميداني — جامعة القصيم

**كلية اللغات والعلوم الإنسانية · قسم الاجتماع والخدمة الاجتماعية**
رئيس القسم: د. عمر النملة · رئيس وحدة التدريب الميداني: د. عبدالله التيجاني

تطبيق ويب وجوال (PWA) لإدارة التدريب الميداني بالكامل. يشمل التوزيع على الجهات والخطابات الرسمية، والتحضير بالتحديد الجغرافي مع كشف التحضير الوهمي، والسجلات الميدانية بالتوقيع الإلكتروني، والتقييم ورصد الدرجات، ولوحات قيادية لحظية واستراتيجية.

| الطبقة | التقنية |
|---|---|
| الواجهة | Next.js 15 (App Router) + React 19 + Tailwind CSS + مكونات بنمط shadcn/ui، واجهة عربية RTL كاملة |
| الخادم | Next.js Route Handlers (Node.js) |
| قاعدة البيانات | PostgreSQL (محلي أو Supabase) عبر Prisma ORM |
| المصادقة | NextAuth (JWT) + تشفير bcrypt + صلاحيات حسب الدور (RBAC) |
| الخرائط | Leaflet / OpenStreetMap |
| الخطابات | HTML بمقاس A4 مع تحويل إلى PDF على الخادم عبر Chromium ورمز تحقق QR |

## 1) التشغيل السريع (محلياً)

المتطلبات: Node.js 20 أو أحدث، وPostgreSQL 14 أو أحدث (أو مشروع Supabase).

```bash
# 1. تثبيت الحزم
npm install

# 2. إعداد المتغيرات
cp .env.example .env
#   عدّل DATABASE_URL و DIRECT_URL و NEXTAUTH_SECRET (openssl rand -base64 32)

# 3. إنشاء الجداول (ترحيلات SQL في prisma/migrations)
npm run db:deploy                       # = prisma migrate deploy

# 4. بيانات تجريبية (اختياري)
npm run db:seed

# 5. التشغيل
npm run dev        # http://localhost:3000
```

> **قاعدة أُنشئت سابقاً بـ `db push`:** اعتمدها كخط أساس مرة واحدة ثم طبّق الترحيلات الجديدة:
> ```bash
> npx prisma migrate resolve --applied 0001_init
> npm run db:deploy
> ```
> الترحيل `0002_official_forms` **إضافي فقط** (لا حذف لأي جدول أو عمود) ومُختبَر على قاعدة فارغة وعلى قاعدة فيها بيانات.

|---|---|
| رئيس القسم | `omar.alnamlah@qu.edu.sa` |
| رئيس وحدة التدريب الميداني | `abdullah.altijani@qu.edu.sa` |

> **تنبيه:** الأسماء في البيانات التجريبية (باستثناء رئيس القسم ورئيس الوحدة) وهمية. **إحداثيات الجهات تقريبية** ويجب استبدالها بالإحداثيات الفعلية لكل جهة قبل التشغيل، وإلا سيُرفض تحضير الطلاب.

### الربط مع Supabase

1. أنشئ مشروعاً في Supabase، ثم انسخ رابطي الاتصال من *Project Settings → Database*.
2. ضع رابط الـ **Pooler** (المنفذ 6543، مع `?pgbouncer=true`) في `DATABASE_URL`، والرابط **المباشر** (المنفذ 5432) في `DIRECT_URL`.
3. نفّذ `npx prisma migrate deploy` ثم `npm run db:seed`.

تستخدم المنصة Supabase كقاعدة PostgreSQL فقط، والمصادقة تتم عبر NextAuth. للانتقال إلى Supabase Auth يكفي استبدال `src/lib/auth/*` لأن بقية الطبقات تعتمد على `requireRole()` فقط.

### النشر (Vercel أو خادم خاص)

```bash
npm run build && npm start
```

- **PDF على الخادم:** يتطلب متصفح Chromium. على خادم خاص ثبّت `chromium` واضبط `CHROME_EXECUTABLE_PATH`. على Vercel استخدم `@sparticuz/chromium`. إذا لم يُضبط المتغير يُحوَّل رابط PDF تلقائياً إلى نسخة الطباعة، ويستطيع المستخدم الحفظ بصيغة PDF من المتصفح.
- **المهمة اليومية:** تسجل الغياب آلياً وترفع التنبيهات الحرجة. جدولها بعد نهاية الدوام (مثلاً 15:00 بتوقيت الرياض = 12:00 UTC):
  ```bash
  curl -X POST https://your-domain/api/cron/daily -H "Authorization: Bearer $CRON_SECRET"
  ```
  على Vercel أضف في `vercel.json`: `{"crons":[{"path":"/api/cron/daily","schedule":"0 12 * * 0-4"}]}`. لاحظ أن Vercel Cron يرسل طلب GET، فأضف GET للمسار أو استخدم مجدولاً خارجياً.
- **HTTPS إلزامي:** المتصفحات لا تسمح بتحديد الموقع إلا على HTTPS أو localhost.
- **الشعار الرسمي:** ضع ملف الشعار في `public/brand/logo.png` واضبط `LOGO_PATH="public/brand/logo.png"`. الملف الحالي `logo.svg` شعار مؤقت فقط.

## 3) مرجع الـ API

كل المسارات تتحقق من الدور في الخادم (`requireRole`) وتحصر البيانات بالطلاب المرتبطين بالمستخدم (`placementScope`). الأخطاء تعود بصيغة `{ error, details? }` وبرسائل عربية.

### الحضور والتحضير
| المسار | الدور | الوصف |
|---|---|---|
| `GET /api/attendance/today` | طالب | جهة اليوم ونطاقها وسجل اليوم |
| `POST /api/attendance/check-in` | طالب | تسجيل الحضور: `{ samples[], deviceId }` |
| `POST /api/attendance/check-out` | طالب | تسجيل الانصراف (يحسب الدقائق) |
| `GET /api/attendance?placementId&from&to&approval&suspicious=1` | الجميع (حسب النطاق) | سجل الحضور |
| `POST /api/attendance/approve` | مشرف ميداني / رئيس التدريب | اعتماد أو رفض فردي أو جماعي، ويعيد احتساب الساعات |
| `POST /api/attendance/manual` | مشرف ميداني | تسجيل غياب أو عذر أو إجازة |
| `POST /api/cron/daily` | Cron (Bearer) | تعليم الغياب والتنبيهات الحرجة |

## 4) قرارات التصميم المهمة

### التحضير الجغرافي وكشف التزييف
- يجمع العميل **4 قراءات GPS متتالية** خلال 15 ثانية بأعلى دقة، ثم يعيد **الخادم** التحقق من كل شيء. لا يُعتمد على أي حساب يجري في المتصفح.
- **النطاق:** 100 م افتراضياً لكل جهة (قابل للتعديل)، مع هامش لا يتجاوز 25 م لتعويض ضعف الإشارة.
- **تقييم المخاطر** (`src/lib/geo/anti-spoof.ts`): أعلام حاسمة تؤدي إلى **الرفض** (موقع وهمي من النظام، دقة ضعيفة، قراءة قديمة، إحداثيات صفرية)، وأعلام مشبوهة تؤدي إلى **القبول مع الإحالة للمراجعة** (دقة غير واقعية، ثبات تام بين القراءات، سفر مستحيل، إحداثيات منخفضة الدقة، جهاز غير الجهاز المسجل). اجتماع مؤشرين قويين يؤدي إلى الرفض.
- كل محاولة، سواء قُبلت أو رُفضت، تُحفظ في `AttendanceAttempt` للتدقيق.
- **الساعات لا تُحتسب إلا بعد اعتماد المشرف الميداني**، وهو خط الدفاع الأخير.
- **حدود معروفة:** لا يمكن لتطبيق ويب كشف تزييف الموقع بنسبة 100%. أقوى إضافة مستقبلية هي تغليف التطبيق بـ Capacitor لقراءة علم `isMock` من نظام أندرويد، والمسار مهيأ لاستقباله (`isMocked`).

### الدرجة النهائية
`40% المشرف الميداني + 40% المشرف الأكاديمي + 20% التحضير والسجلات`. الأوزان مخزنة في `AcademicTerm` وقابلة للتعديل لكل فصل، ويُرفض أي مجموع لا يساوي 100. مكوّن التحضير يُحسب هكذا: نصفه لنسبة إنجاز الساعات، ونصفه لنسبة السجلات الأسبوعية المرفوعة، ويُخصم منه درجة عن كل غياب بلا عذر (بحد أقصى نصف المكوّن). سلم التقديرات: A+ من 95، وA من 90 … وF أقل من 60. لا يمكن الاعتماد إذا كان أحد التقييمين ناقصاً.

### إدارة الجهات والإحداثيات
- **منتقي الموقع**: انقر على الخريطة أو اسحب الدبوس، مع طبقة «قمر صناعي» لتحديد المدخل بدقة. يمكن أيضاً لصق رابط خرائط Google (بما فيها الروابط المختصرة `maps.app.goo.gl`) أو استخدام «موقعي الحالي» عند زيارة الجهة.
- في روابط Google من نوع place يُعتمد **دبوس المكان** (`!3d…!4d…`) لا مركز الكاميرا (`@…`)، لأن الأخير قد يبعد عن الموقع الفعلي مئات الأمتار.
- الإحداثيات مقيدة بنطاق المملكة لاكتشاف الأخطاء الشائعة مثل تبديل خط الطول بخط العرض.
- كل تغيير في موقع جهة أو في نطاقها يُسجَّل في سجل التدقيق بالقيم السابقة والجديدة ومسافة النقل، ويظهر تحذير إذا كان للجهة متدربون حاليون.
- **لا تُحذف** جهة لها إسنادات، بل **تُوقَف**، حفاظاً على السجلات التاريخية.

### بنود التقييم
- تُحسب نسبة الطالب من مجموع البنود المنطبقة على **تخصصه**، ويعرض المحرر مجموع كل تخصص لحظياً ويُنصح بأن يكون 100.
- **القفل التلقائي**: بمجرد رصد أول تقييم نهائي باستمارة ما في الفصل تُقفل بنودها، حتى يُقيَّم جميع الطلاب بالمقياس نفسه. كذلك تُقفل الأوزان بعد اعتماد أول نتيجة.

### التقارير الميدانية
- ست قوالب: **دراسة حالة، خطة تدخل اجتماعي، خدمة الجماعة** (للخدمة الاجتماعية)، و**بحث ميداني، مسح اجتماعي** (لعلم الاجتماع)، و**التقرير الختامي** (للتخصصين).
- كل قالب **تعريف تصريحي** في `src/lib/report-templates.ts`، ومنه تُولَّد الواجهة والعرض والطباعة والتحقق في الخادم. لتعديل نموذج أو إضافة حقل يكفي تعديل هذا الملف. التحقق صارم: يرفض الخادم أي حقل غير معرّف أو نوع خاطئ.
- **مسار العمل**: مسودة (مع حفظ تلقائي) ← رفع ← توقيع المشرف الميداني أو إعادته ← اعتماد المشرف الأكاديمي بدرجة استرشادية أو إعادته. إعادة تقرير موقَّع تُسقط توقيعه لأن المحتوى سيتغير.
- **السرية**: دراسة الحالة وخدمة الجماعة تفرضان اسماً رمزياً وإقراراً بموافقة العميل.
- الطباعة وحفظ PDF متاحان من المتصفح بصيغة A4 مع الترويسة والتوقيع.

### التوقيع الإلكتروني
صورة التوقيع (PNG) ومعها **بصمة SHA-256 لمحتوى المستند وقت التوقيع**، إضافة إلى عنوان IP والوقت. أي تعديل لاحق يمكن كشفه بمقارنة البصمة. هذا مُختبَر: أي تعديل مباشر على محتوى تقرير موقَّع في قاعدة البيانات يغيّر البصمة فيُكتشف.
