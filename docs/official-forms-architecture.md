# معمارية النماذج الرسمية للتدريب الميداني

المرجع: «نماذج التدريب الميداني لمرحلة البكالوريوس ١٤٤٧هـ – ٢٠٢٦م»، قسم الاجتماع والخدمة الاجتماعية، كلية اللغات والعلوم الإنسانية، جامعة القصيم (29 جدولاً في 16 نموذجاً).

---

## 1. القرار المعماري: مظروف موحّد + جداول مُنمذَجة

```
                       ┌──────────────────────── FieldForm (المظروف) ────────────────────────┐
 Placement ──1:N──►    │ kind · sequence (رقم ( )) · status · اعتماد مؤسسي · اعتماد أكاديمي · قفل │
                       └──┬─────────────┬──────────────┬───────────────┬──────────────────────┘
                          │ 1:1         │ 1:N          │ 1:N           │ 1:N
                ┌─────────▼────────┐  FormSignature  Attachment     FormComment
                │ جدول تفصيلي لكل   │  (خانات التوقيع) (الشواهد/الختم) (جولات المراجعة)
                │ نموذج (typed)     │
                └──────────────────┘
 مستقلة (ليست لطالب واحد):  SupervisionMeeting (اجتماع إشرافي جماعي) · AttendanceSheet (كشف حضور يومي للمؤسسة)
```

**لماذا هذا الشكل؟**

| البديل | المشكلة |
|---|---|
| جدول واحد بمحتوى JSON (البنية السابقة `FieldReport`) | لا يمكن الاستعلام عن الإحصاءات (عدد المستفيدين، نتائج دراسات الحالة، البرامج المنفذة) ولا توجد قيود على مستوى القاعدة. |
| جدول مستقل كامل لكل نموذج | يتكرر منطق سير العمل والتوقيع والمرفقات 11 مرة. |
| **مظروف + تفاصيل مُنمذَجة (المعتمد)** | سير العمل والتوقيع والمرفقات تُكتب مرة واحدة، وكل نموذج مُنمذَج بحقوله الرسمية. |

**قواعد النمذجة:**
- الحقول الرقمية التي يُبنى عليها إحصاء تُحفظ أعمدةً مُنمذَجة، مثل أعداد الأعضاء والمستفيدين والأخصائيين ونتيجة التقييم النهائي.
- النصوص السردية الطويلة تُحفظ في أعمدة `Text`.
- الصفوف المتكررة ذات البنية تُحفظ في جداول فرعية، مثل أفراد الأسرة وأسابيع الخطة وصعوبات المقابلة وحضور الاجتماع.
- القوائم البسيطة تُحفظ في `String[]`، مثل المشكلات الفرعية والإيجابيات والسلبيات.
- خانات الاختيار (√) في النماذج تُحفظ `Boolean` أو تعداداً (enum)، وعند الاختيار المتعدد مصفوفة تعدادات.
- **النماذج الفردية** (المباشرة، التقرير التعريفي، الخطة) رقمها `sequence = 1` دائماً، فيمنع القيد الفريد `(placementId, kind, sequence)` تكرارها على مستوى القاعدة. **النماذج المرقّمة** («رقم ( )») تتزايد أرقامها.

## 2. خريطة النماذج ← النماذج البرمجية (Prisma)

| # | النموذج الرسمي | `FormKind` / الجدول | ملاحظات التصميم |
|---|---|---|---|
| — | غلاف «السجل المهني للتدريب الميداني» و«… بالمحاكاة» | `CourseSection.mode` = FIELD / SIMULATION | الغلاف يُولَّد عند التصدير. |
| — | بيانات المتدرب/ـة (تدريب ميداني رقم، المسار، رقم الشعبة) | `CourseSection` + `Placement` + `Organization` | لا جدول مستقل؛ بيانات مشتقة. |
| 1 | مباشرة الطالب/ـة لمؤسسة التدريب | `COMMENCEMENT` / `CommencementForm` | اليوم الثابت، والفترة، والإقرار، ولقطة جوال المشرف وبريد المؤسسة واسم المدير وقت التوقيع، و**ثلاث خانات توقيع** (الطالب، المشرف المؤسسي، المدير مع الختم). |
| 2 | تقرير تعريفي بمؤسسة التدريب (8 أقسام) | `ORGANIZATION_PROFILE` / `OrganizationProfileReport` + `OrgProfessionalGroup` | «عدد المهنيين من التخصصات الأخرى وتصنيفهم» جدول فرعي (التخصص، العدد). بعد الاعتماد تُحدَّث أرقام الجهة في الدليل. |
| 3 | نموذج خطة التدريب الميداني | `TRAINING_PLAN` / `TrainingPlan` + `TrainingPlanWeek` | الأسبوع، والمهام، والمسؤول عن أداء المهمة. |
| 4 | تسجيل المهارات والمعارف الأسبوعية | `SKILLS_LOG` / `SkillsLog` | لكل يوم تدريبي: حتى 6 موضوعات، وسرد المهارات، وسرد المعارف، والصعوبات، والصور والشواهد (`Attachment`)، وربط اختياري بأسبوع الخطة. |
| 5 | تقرير البرنامج الجماعي | `GROUP_PROGRAM` / `ProgramReport` | الأجزاء: الإحصائي، والأهداف، والإعدادي، والقصصي، والتحليلي، والتقييم. |
| 6 | تقرير البرنامج المجتمعي | `COMMUNITY_PROGRAM` / `ProgramReport` | الأجزاء: الإحصائي، والأهداف، والتخطيطي، والتنفيذي، والتقييم. الجدول مشترك مع الجماعي، والتحقق من الأجزاء الإلزامية حسب النوع. |
| 7 | تسجيل الموقف السريع (المدرسة) | `QUICK_SITUATION` / `QuickSituation` (domain = SCHOOL) | الاسم اختياري، والصف الدراسي. |
| 8 | تسجيل الموقف السريع (المستشفى) | `QUICK_SITUATION` / `QuickSituation` (domain = MEDICAL) | رقم الملف، ونوع المراجع (5 خيارات)، والقسم. |
| 9 | دراسة الحالة وفقاً لخطوات التدخل المهني | `CASE_STUDY` / `CaseStudy` + `CaseFamilyMember` | التقدير (الجوانب الأربعة والبيئية والتكوين الأسري)، والتخطيط، والتدخل، والتقييم (المبدئي 5×√، والمرحلي 3×2، والنهائي)، والإنهاء (المخطط 5×√ أو غير المخطط 3)، والمتابعة (الفترة، والأهداف، والأسلوب، والنتيجة). |
| 10 | تسجيل المقابلة المهنية | `INTERVIEW` / `InterviewRecord` + `InterviewDifficulty` | رقم المقابلة = `sequence`، وربط اختياري بدراسة الحالة. |
| 11 | القراءات | `READING` / `ReadingRecord` | نوع المصدر (3)، وعناصر APA مُنمذَجة تُولَّد منها صيغة التوثيق آلياً. |
| 12 | سجل الاجتماعات الإشرافية الجماعية | `SupervisionMeeting` + `MeetingAttendance` | أعداد الحضور والغياب (بعذر وبدونه) **محسوبة** لا مُدخلة، وأمين الاجتماع أحد المتدربين، وخانات: رئيس الاجتماع، والأمين، والأعضاء. |
| 13 | سجل الحضور والانصراف | `AttendanceSheet` + `AttendanceRecord` | الأوقات من التحضير الجغرافي، والكشف اليومي يوقّعه المشرف المؤسسي مع بصمة SHA-256 للسجلات. |

**إضافات على الجداول القائمة:**
- `Organization`: `phone`، و`directorName`، و`socialWorkersCount`، و`beneficiariesCount`، والختم عبر `Attachment(kind=STAMP)`.
- `Placement`: `sectionId`، و`shift`، و`commencedAt`.

## 3. الصلاحيات (RBAC)

**مفتاح الرموز:**

| الرمز | المعنى |
|---|---|
| ✎ | إنشاء وتعديل المسودة |
| ✓م | توقيع واعتماد مؤسسي |
| ✓أ | اعتماد أكاديمي |
| ↩ | إعادة للتعديل |
| 👁 | عرض |
| ⬇ | تصدير PDF |

| النموذج | الطالب | المشرف المؤسسي | المشرف الأكاديمي | رئيس الوحدة | رئيس القسم |
|---|---|---|---|---|---|
| المباشرة | ✎ + توقيع | ✓م + توقيع المدير والختم | 👁 ✓أ (إحاطة) | 👁 ⬇ | 👁 |
| التقرير التعريفي | ✎ | ✓م ↩ (صحة بيانات الجهة) | ✓أ ↩ | 👁 ⬇ | 👁 |
| خطة التدريب | ✎ | ✎ في الصفوف قبل التوقيع، ✓م ↩ | ✓أ ↩ | 👁 ⬇ | 👁 |
| سجل المهارات والمعارف | ✎ + مرفقات | ✓م ↩ | ✓أ ↩ | 👁 ⬇ | 👁 |
| البرنامج الجماعي والمجتمعي | ✎ | ✓م ↩ | ✓أ ↩ + درجة | 👁 ⬇ | 👁 |
| المواقف السريعة | ✎ | ✓م ↩ | ✓أ ↩ | 👁 ⬇ | 👁 |
| دراسة الحالة | ✎ | ✓م ↩ | ✓أ ↩ + درجة | 👁 ⬇ | 👁 |
| المقابلة المهنية | ✎ | ✓م ↩ | ✓أ ↩ | 👁 ⬇ | 👁 |
| القراءات | ✎ | — (لا يمرّ عليه) | ✓أ ↩ | 👁 ⬇ | 👁 |
| الاجتماع الإشرافي | الأمين: ✎ المحضر، الأعضاء: توقيع | — | ✎ ينشئ ويحضّر، رئيس الاجتماع يعتمد | 👁 ⬇ | 👁 |
| كشف الحضور اليومي | تحضير جغرافي | ✓م توقيع الكشف | 👁 | 👁 ⬇ | 👁 |

**قواعد عامة:**
- لا يرى المشرفون المسودات.
- الرؤية محصورة بالإسناد عبر `placementScope`.
- كل انتقال يُسجَّل في `AuditLog`.
- بعد اعتماد الدرجة النهائية يُضبط `lockedAt` فلا تعديل ولا إعادة.
- «رئيس القسم» قراءة فقط.

## 4. سير العمل (آلة حالات واحدة وسياسة لكل نموذج)

```
DRAFT ──submit──► SUBMITTED ──sign(مؤسسي)──► SIGNED ──approve(أكاديمي)──► REVIEWED ──(اعتماد الدرجة)──► locked
  ▲                   │                        │
  └──── RETURNED ◄────┴──── return (بملاحظة) ───┘      * إعادة نموذج موقَّع تُسقط توقيعه (المحتوى سيتغير)
```

سياسة كل نموذج تُعرَّف في الكود (`src/lib/forms/policy.ts`):
- **الخانات المطلوبة لكل انتقال:** المباشرة تتطلب STUDENT عند الرفع، ثم FIELD_SUPERVISOR + ORG_DIRECTOR عند التوقيع.
- **تجاوز المرحلة المؤسسية:** القراءات تنتقل من SUBMITTED إلى REVIEWED مباشرة.
- **آثار جانبية عند الاعتماد:**
  - اعتماد المباشرة يجعل الإسناد `ACTIVE`، ويضبط `commencedAt`، ويجعل `workDays = [اليوم الثابت]`، ويسجّل `shift`.
  - اعتماد التقرير التعريفي يحدّث أعداد الجهة في الدليل.

## 5. واجهات الإدخال (المرحلة 3)

كل نموذج **وصف تصريحي** واحد (`src/lib/forms/ui/specs.ts`) بعناوين الدليل الحرفية، يرسمه عارض واحد (`FormRenderer`) للتحرير والقراءة والطباعة. اختبارات التغطية تضمن تطابق الوصف مع مخطط Zod، والحقول الإلزامية مشتقة من قواعد الرفع نفسها (`checkSubmit`).

| المكوّن (`src/components/forms/`) | الاستخدام |
|---|---|
| `NarrativeField` | الأجزاء السردية (القصصي، والتحليلي، والمهارات والمعارف): عدّاد كلمات وحد أدنى، و**كاشف قوائم نقطية** ينبّه لأن النموذج يشترط «سردية علمية وليس نقاطاً». |
| `RowsField` · `ListField` | التكوين الأسري، وأسابيع الخطة، والصعوبات، والإيجابيات والسلبيات. |
| `ChoiceField` · `MultiChoiceField` · `YesNoField` · `CheckField` | خانات √ (التقييم المبدئي، والإنهاء المخطط، والمتابعة) بنفس ترتيب الجدول الرسمي. |
| `ActionDialog` + `SignaturePad` | خانات التوقيع التي يتطلبها الإجراء: الطالب عند الرفع؛ المشرف المؤسسي ومدير المؤسسة (على جهاز المشرف) مع وسم «بالختم» في المباشرة. |
| `Evidence` | «الصور والشواهد والأدلة»: ضغط الصور في المتصفح (2000px)، و**إزالة بيانات EXIF/GPS** في الخادم، وحد 5MB. |
| `FormWorkspace` | شاشة النموذج: حفظ تلقائي للحقول المعدّلة فقط، وقائمة النواقص لحظياً بروابط إلى الحقول، وأزرار الإجراءات من `allowedActions`، ومسار الحالة، والتواقيع، وملاحظات المراجعة. |

**النص السردي:** يُحفظ نصاً عادياً بفقرات، لا HTML. هذا أأمن (لا ثغرات XSS)، ويُطبع في PDF بدقة، ويسمح بعدّ الكلمات. يمكن إضافة تنسيق خفيف لاحقاً إن طلب القسم ذلك.

**مخطط التحقق:** لكل نموذج مخطط Zod واحد (`src/lib/forms/schemas/<kind>.ts`) يُستخدم في الواجهة والخادم معاً، بنمطين: «مسودة» مرن و«رفع» صارم.

## 6. تصدير PDF الرسمي (المرحلة 5)

المواصفات مستخرجة من ملف النماذج:
- A4.
- **الترويسة:** العربية يميناً (المملكة العربية السعودية، وزارة التعليم، جامعة القصيم، كلية اللغات والعلوم الإنسانية، قسم الاجتماع والخدمة الاجتماعية)، والشعار الرسمي في الوسط، والإنجليزية يساراً.
- **التذييل:** «نماذج التدريب الميداني لمرحلة البكالوريوس ١٤٤٧ هـ – ٢٠٢٦ م» مع رقم الصفحة.
- **الخط:** Traditional Arabic بحجم 14pt للمتن و16pt للعناوين. هذا الخط ملك Microsoft ولا يُضمَّن في خادم ويب، والبديل المقترح **Amiri** وهو نسخ مشابه بترخيص حر.
- **ألوان الجداول الرسمية:** كحلي `#0F486E`، وفيروزي `#18C5B8` و`#0D89A8`، ورمادي `#F2F2F2`.
- **خانات التوقيع والختم:** إطارات بأسماء الموقّعين، مع صورة التوقيع وختم المؤسسة إن وُقّع رقمياً.

**أنواع المخرجات:**
1. PDF لكل نموذج.
2. **«السجل المهني» الكامل** بترتيب الدليل الرسمي: الغلاف، ثم المباشرة، ثم بيانات المتدرب، ثم التعريفي، ثم الخطة، ثم سجلات المهارات، ثم البرامج، ثم المواقف، ثم دراسات الحالة، ثم المقابلات، ثم القراءات، ثم الاجتماعات، ثم كشوف الحضور.
3. رمز QR للتحقق.

**التقنية:** قوالب HTML/CSS تُطبع عبر Chromium (البنية المستخدمة حالياً للخطابات).

## 8. قرارات القسم

| # | المسألة | القرار | الأثر في النظام |
|---|---|---|---|
| 1 | طلاب علم الاجتماع | **يستخدمون النماذج الرسمية نفسها** (قابل للتعديل لاحقاً) | كل النماذج متاحة للتخصصين. قوالب «البحث الميداني» و«المسح الاجتماعي» السابقة تبقى نماذج إضافية (`CUSTOM`). |
| 2 | الهوية البصرية | **توحيد الواجهة مع الهوية الرسمية** (الكحلي والفيروزي) | `src/lib/brand.ts` مصدر واحد للألوان، والشعار الرسمي في الواجهة والخطابات. |
| 3 | الاسم الإنجليزي للكلية | **كما ورد في النماذج**، ويمكن تعديله لاحقاً | `INSTITUTION.en` في `src/lib/labels.ts`. |
| 4 | رقم الملف الطبي | **معتمد:** يظهر كاملاً للطالب والمشرف المؤسسي **والمشرف الأكاديمي المسؤول عن الطالب**، ومخفياً لغيرهم (`•••812`) | `mayViewHealthIdentifiers` في `src/lib/forms/privacy.ts`، ومُختبَر في الوحدات وعبر HTTP. |
| 5 | ختم المؤسسة | الخياران مدعومان | رفع ختم رقمي: `POST /api/organizations/:id/stamp`. |
| 6 | التدريب بالمحاكاة | **معتمد:** لا مقر تدريب فعلي، فتُستثنى «مباشرة التدريب» و«التقرير التعريفي بالمؤسسة» و«سجل الحضور والانصراف (الجغرافي/اليومي)»، وتبقى النماذج المهنية (دراسات الحالة، والمواقف السريعة، والتقارير، والسجل الأسبوعي) | `SITE_BOUND_KINDS` و`policyFor(kind, mode)`: بلا مشرف مؤسسي، فتذهب النماذج إلى المشرف الأكاديمي مباشرة. التحضير مرفوض في الخادم، ورابطه مخفي، وصفحته تحوّل إلى السجل المهني. مكوّن الحضور في الدرجة يُحتسب من انتظام السجل الأسبوعي. |
| 7 | وزن المشرف المؤسسي (40%) في المحاكاة | **معتمد:** يُنقل كاملاً إلى المشرف الأكاديمي (80%)، وتُخفى بطاقة المشرف المؤسسي لطلاب المحاكاة | `fieldApplicable=false` في محرك الدرجات، وتُحفظ الأوزان الفعلية في `breakdown.effectiveWeights`. اعتماد النتائج وكشف الدرجات يعرضان «لا ينطبق». |

### التحول من السجلات القديمة

1. **الترحيل** (`npm run db:migrate-legacy -- --apply`): كل `FieldReport` و`Logbook` يصبح `FieldForm(kind=CUSTOM)` بمحتواه وحالته وتواريخه ودرجته وتوقيعه (بالبصمة نفسها) وملاحظاته. المعرّف القديم يُحفظ في `data._legacy`، فإعادة التشغيل لا تكرر شيئاً. نُفّذ على البيانات التجريبية: 51 سجلاً، و1 توقيع، وإعادة التشغيل رحّلت 0.
2. **الاستمرارية:** ما كان قيد المراجعة عند التحول يظهر في قوائم الاعتماد تحت «سجلات مرحّلة من النظام السابق» بشارة «مرحّل»، ويُستكمل توقيعه واعتماده بسير العمل الجديد. ويظهر للطالب في «الأرشيف»، والمعاد منه يظهر في «الخطوة التالية».
3. **الصفحات القديمة** (`/student/logbooks`، و`/student/reports`، و`/field-supervisor/logbooks`، و`/academic-supervisor/reports`) تحوّل إلى السجل المهني أو قائمة الاعتماد. روابط التقارير القديمة `/…/reports/:id` تحوّل إلى النموذج المرحَّل نفسه.
4. **واجهات API القديمة:** القراءة (`GET`) باقية للأرشيف. الكتابة (`POST /api/reports`، و`PATCH`/`DELETE /api/reports/:id`، و`…/sign`، و`…/review`، و`POST /api/logbooks`، و`/api/logbooks/:id/sign`) تعيد **410** مع الإشارة إلى `/api/forms`، حتى لا تُكتب بيانات في جداول لم تعد تُعرض.
5. الجداول القديمة **لم تُحذف** (للتدقيق والرجوع). يمكن حذفها في إصدار لاحق بعد اعتماد القسم.

### ما تحققه اختبارات الواجهة (`npm run test:e2e:ui`)

- **طالب ميداني جديد:** السجل مقفل حتى المباشرة، ثم تعبئة المباشرة بالحفظ التلقائي والرفع بتوقيع مرسوم.

## 11. المرحلة 4: الاجتماعات الإشرافية وكشف الحضور اليومي الموقَّع

### سجل الاجتماعات الإشرافية الجماعية (`/meetings`)

- **المجموعة الإشرافية:** الفصل × مؤسسة التدريب × المشرف الأكاديمي. أعضاؤها متدربو المؤسسة المسندون إليه، والاجتماعات مرقّمة داخلها «رقم ( )».
- **الترويسة الرسمية:** مؤسسة التدريب، ومجال التدريب، والمشرف/ـة الأكاديمي، وإجمالي المتدربين، وإجمالي الاجتماعات.
- **أولاً / الجزء الإحصائي:** اليوم (من التاريخ)، والتاريخ، والتوقيت، والمدة، والمكان. عدد الحضور والغياب وأسماء الغياب بعذر وبدون عذر **محسوبة من سجل الحضور** لا مُدخلة.
- **ثانياً / جدول الأعمال:** «التصديق على محضر الاجتماع السابق» يُضاف آلياً عدا الاجتماع الأول، ثم البنود، ثم «ما يستجد من الأعمال» بنداً ثابتاً.
- **ثالثاً / محضر الاجتماع:** نص سردي، 60 كلمة على الأقل.
- **رابعاً / القرارات والتوصيات:** قائمة.
- **التواقيع:** الأعضاء (الحاضرون) | أمين الاجتماع | رئيس الاجتماع.

| الخطوة | من | ماذا |
|---|---|---|
| إعداد | المشرف الأكاديمي (رئيس الاجتماع) | ينشئ الاجتماع (رقم تالٍ)، ويسجّل الحضور والأعذار، ويحدد أمين الاجتماع من الحاضرين، وجدول الأعمال. |
| المحضر | أمين الاجتماع (طالب) | يكتب المحضر والقرارات فقط (مخطط Zod مستقل يرفض بقية الحقول)، ثم **يرفعه بتوقيعه**. |
| الاعتماد | رئيس الاجتماع | **يعتمد بتوقيعه** فيُقفل المحضر، أو **يعيده بملاحظة** فيُلغى توقيع الأمين. |

- **الرؤية:** المسودة لرئيس الاجتماع وأمينه فقط؛ بقية الأعضاء بعد الرفع؛ رئيس الوحدة ورئيس القسم للاطلاع؛ المشرف المؤسسي لا يصل إليها.
- **البصمة:** كل توقيع يحفظ بصمة SHA-256 لمحتوى المحضر وقت التوقيع.
- **الظهور في الواجهات:**
  - في «السجل المهني» للطالب: القسم مع حضوره ودوره أميناً.
  - في قائمة اعتماد المشرف الأكاديمي: المحاضر المرفوعة.
- **ترحيل القاعدة:** `0003_meetings_workflow` يضيف `submittedAt` و`approvedAt` و`returnNote`.

### سجل الحضور والانصراف اليومي (`/attendance-sheets`)

- **النطاق:** كشف واحد لكل مؤسسة ويوم، يضم متدربيها في التدريب الميداني (لا المحاكاة) ممن يكون هذا اليوم ضمن مدتهم وأيام تدريبهم.
- **الترويسة الرسمية:** اسم المؤسسة وهاتفها، والمدير، والبريد، والمشرف المؤسسي، وإجمالي المتدربين، والمشرف الأكاديمي، وتاريخا البدء والانتهاء، والعنوان، والأسبوع/اليوم/التاريخ.
- **الجدول:** م | اسم الطالب/ـة | وقت الحضور | التوقيع | وقت الانصراف | التوقيع.
  - الأوقات من التحضير الجغرافي.
  - «التوقيع» أمام الطالب هو تحضيره الموثّق بالموقع: «تحضير جغرافي» أو «يدوي».
- **التوقيع:** المشرف المؤسسي لتلك المؤسسة فقط، ولا يُوقَّع كشف يوم لم يأتِ، ولا كشف اليوم الحالي قبل تسجيل انصراف الحاضرين. عند التوقيع:
  1. يُسجَّل غياب من لم يحضر في يوم تدريبه، كما تفعل مهمة الغياب اليومية.
  2. تُربط سجلات اليوم بالكشف، وتُحفظ **بصمة SHA-256** لحالة كل متدرب وأوقاته ومدته (`src/lib/attendance-sheet.ts`).
  3. **يُقفل اليوم:** يُرفض التحضير والانصراف والتسجيل اليدوي وتعديل المدة لذلك اليوم (409).
- **التحقق:** صفحة الكشف تعيد حساب البصمة في كل عرض، وتُظهر «مطابق» أو «تغيّرت السجلات بعد التوقيع». أي تعديل مباشر على القاعدة يُكتشف.
- **اعتماد الساعات** يبقى مستقلاً في «المتدربون والحضور»: قرار الاعتماد لا يدخل في البصمة، فلا يغيّر الكشف.
- **الظهور في الواجهات:**
  - في قائمة اعتماد المشرف المؤسسي: تنبيه بعدد الكشوف غير الموقّعة.
  - في «السجل المهني» للطالب الميداني: عدد أيامه المدرجة في كشوف موقّعة.
  - للمشرف الأكاديمي والرئيسين: عرض فقط.

## 12. المرحلة 5: مخرجات PDF الرسمية

### المحرك (`src/server/pdf/`)

| الملف | الدور |
|---|---|
| `engine.ts` | HTML ← Chromium (puppeteer-core) ← PDF بمقاس A4. متصفح واحد يُعاد استخدامه ويُغلق بعد دقيقة خمول، ويُكتشف Chrome/Edge/Chromium تلقائياً. الخطوط **مضمّنة محلياً**: Amiri للمتن (بديل Traditional Arabic المعتمد في الدليل)، وIBM Plex Sans Arabic للجداول، فلا يحتاج التوليد إلى الإنترنت. عند غياب المتصفح تُعاد نسخة HTML للطباعة. |
| `layout.ts` | **الإطار الرسمي**: ترويسة الدليل (المملكة العربية السعودية، وزارة التعليم، جامعة القصيم، كلية اللغات والعلوم الإنسانية، قسم الاجتماع والخدمة الاجتماعية) بالعربية والإنجليزية والشعار، **تتكرر في كل صفحة**. تذييل يحمل وصف المستند، و**بصمة المحتوى SHA-256**، و**رمز QR** للتحقق، وترقيم الصفحات. يتضمن أيضاً خانات التوقيع وأماكن الختم. |
| `spec-html.ts` | يرسم كل نموذج من **وصفه التصريحي نفسه** المستخدم في الواجهة: الحقول القصيرة في جداول رسمية بعمودين، والنصوص السردية فقرات، والجداول بترويسة كحلية، والاختيارات بخانات (√)، فلا يوجد قالب منفصل يتقادم. |
| `documents.ts` | النموذج، ومحضر الاجتماع، وكشف الحضور، والسجل المهني الكامل. |

### التواقيع والأختام
- خانات التوقيع حسب **سياسة كل نموذج**. مثال المباشرة: الطالب، والمشرف المؤسسي، ومدير المؤسسة (الختم والتوقيع).
- يلي ذلك خانة «اعتماد المشرف الأكاديمي» بتاريخ الاعتماد والدرجة.
- الموقَّع منها يُطبع بصورة التوقيع واسم الموقّع ووقته.
- **ختم المؤسسة المرفوع** يُطبع على خانة المدير إن وقّع «بالختم».
- الخانات غير الموقّعة تُطبع **خطاً للتوقيع وتاريخاً فارغاً، ودائرة للختم**، ليُستكمل النموذج يدوياً إن لزم.

### السجل المهني الكامل
الأجزاء بالترتيب:
1. **الغلاف:** «السجل المهني للتدريب الميداني» أو «… بالمحاكاة»، مع بيانات المتدرب.
2. **المحتويات:** مع حالة كل نموذج.
3. **النماذج المرفوعة والمعتمدة** بترتيب الدليل، كل نموذج يبدأ بصفحة جديدة ويحمل بصمته ورمز تحققه. المسودات لا تُدرج.
4. **سجل الاجتماعات الإشرافية.**
5. **سجل الحضور والانصراف:** في الميداني فقط، ومن الكشوف الموقّعة **بسطر الطالب وحده** حفاظاً على خصوصية بقية المتدربين.

### الصلاحيات والخصوصية
- كل مسار PDF يمر **بصلاحية التصدير نفسها** التي تحكم الواجهة، وبالإخفاء نفسه. مثال: رقم الملف الطبي يُطبع مخفياً لرئيس الوحدة وكاملاً للمشرفَين المسؤولَين.
- صفحة التحقق العامة `/verify/f/:id` تعرض نوع المستند والتواقيع وتواريخها وحروف اسم الطالب الأولى فقط. تُظهر «مطابق» أو «تغيّر بعد طباعة هذه النسخة» بمقارنة البصمة المطبوعة بالمحتوى الحالي.
